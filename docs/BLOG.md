# Blog และพื้นที่เขียนบทความของชิดใจ

พัฒนา 3 พฤศจิกายน 2026 สำหรับการเผยแพร่เนื้อหาที่ทีมงานเขียนและตรวจเอง ไม่มีการสร้างหรือเผยแพร่บทความด้วย AI อัตโนมัติ

## หน้าสำหรับใช้งาน

- ผู้อ่าน: `https://www.chordjai.life/blog` และ `/blog/{slug}` เปิดอ่านได้โดยไม่ต้องเข้า LINE
- ผู้เขียน: `https://admin.chordjai.life/blog` ใช้ username/password ชุดเดียวกับ Dashboard และเซสชันผู้ดูแลเดิม
- หน้า Landing มีเมนู Blog; หน้าอ่านบทความเชื่อมกลับหน้าแรก หน้า Product และการเริ่มใช้งานชิดใจ
- บทความเลือกภาษาไทยหรืออังกฤษเป็นรายบทความ รายการบทความแยกตามภาษา ไม่มีการแปลเนื้อหาที่ผู้เขียนไม่ได้เขียนไว้

## เปิดใช้งาน

1. สำหรับฐานข้อมูลปัจจุบันรุ่น **27** ให้ผู้ดูแลรันไฟล์ **`supabase/upgrade-27-to-28.sql` ทั้งไฟล์** ใน Supabase SQL Editor โดยเปิดเป็น query ใหม่ รันซ้ำได้และตรวจฐานรุ่นเดิมก่อนแก้ไข ไม่ใช้ `bootstrap.sql` บนฐานข้อมูลที่มีข้อมูลอยู่แล้ว
2. หากฐานข้อมูลเก่ากว่ารุ่น 27 ให้ใช้ `supabase/diagnostic.sql` ตรวจสถานะก่อน และใช้ `supabase/upgrade.sql` ฉบับปัจจุบันสำหรับฐานที่สคริปต์รู้จัก
3. Deploy backend, owner-app และ admin-console ฉบับนี้หลังอัปเกรด SQL
4. ไม่ต้องสร้าง repository หรือ Vercel project ใหม่ และ **ไม่ต้องเพิ่ม env ใหม่** ใช้ `API_ORIGIN`, `ADMIN_DASHBOARD_USERNAME`, `ADMIN_DASHBOARD_PASSWORD_HASH`, `ADMIN_DASHBOARD_ORIGIN` และ private `BLOB_READ_WRITE_TOKEN` เดิม หากยังตั้งรหัส Dashboard ไม่ถูกต้อง ให้คัดลอกค่า `scrypt:...` จากไฟล์ส่วนตัว `local-secrets/dashboard-backend.env` ไม่ใช่รหัสผ่านจริง

## วิธีเขียน

เริ่มบทความใหม่ เลือกภาษา แล้วเขียนเนื้อหาได้ทันที ใช้หัวข้อระดับ 2/3 ย่อหน้า เว้นบรรทัด ตัวหนา เอียง ขีดเส้นใต้ รายการหัวข้อ รายการตัวเลข คำพูดอ้างอิง ตาราง ลิงก์ และเส้นคั่น พร้อม Undo/Redo มีแม่แบบคู่มือ Q&A เรื่องเล่า และเช็กลิสต์เป็นโครงที่แก้เองได้

อัปโหลด JPG/PNG/WebP ไม่เกิน 3.5 MB ต่อรูป ระบบปรับภาพให้ด้านยาวไม่เกิน 2,000 px ตัด metadata และเก็บ WebP ในพื้นที่ Blog แยกจากรูปสัตว์และไดอารี่ส่วนตัว ใส่คำอธิบายภาพสำหรับผู้ที่อ่านด้วย screen reader และปรับความกว้าง/การจัดวางรูปผ่านเครื่องมือของ editor ได้ มีรูปปกและคำบรรยายภาพประกอบ

ใส่ URL slug เป็นอักษรอังกฤษ ตัวเลข และขีดกลาง เช่น `prepare-cat-vet-visit` พร้อมชื่อผู้เขียน หมวดหมู่ แท็ก ข้อความย่อ และข้อมูล SEO ชื่อบทความและ URL จะอยู่ในหน้ารายการและผลการแชร์ด้วย

## บันทึก เผยแพร่ และยกเลิก

- **บันทึกฉบับร่าง** เก็บงานโดยยังไม่เผยแพร่ เมื่อแก้บทความที่เผยแพร่แล้ว ผู้อ่านยังเห็นรุ่นเดิมจนกดเผยแพร่การแก้ไข
- **ดูตัวอย่าง** ตรวจการจัดหน้าและรูปของฉบับร่างในพื้นที่ผู้ดูแล รูปฉบับร่างต้องมีเซสชันผู้ดูแลจึงเปิดได้
- **เผยแพร่** ตรวจชื่อบทความ slug ผู้เขียน เนื้อหา และคำอธิบายรูปก่อน สำเนาที่เผยแพร่แยกจากงานที่กำลังเขียน
- หลังเผยแพร่ครั้งแรก **slug และภาษาคงเดิม** เพื่อรักษาลิงก์ หากต้องการภาษาอื่นให้สร้างอีกบทความ
- **ยกเลิกเผยแพร่** นำหน้าออกจากรายการและ sitemap และทำให้ URL สาธารณะคืน 404 โดยยังเก็บต้นฉบับไว้ รูปที่ไม่อ้างในบทความสาธารณะอื่นจะเปิดสาธารณะไม่ได้
- **เก็บเข้าคลัง** ซ่อนบทความโดยไม่ลบเนื้อหาถาวร นำกลับมาเป็นฉบับร่างและตรวจเองก่อนเผยแพร่อีกครั้ง
- หากมีการแก้จากอีกหน้าต่าง ระบบแจ้ง version conflict และเก็บสิ่งที่กำลังพิมพ์ไว้ให้ตรวจ แทนการเขียนทับอีกรุ่นเงียบ ๆ

## ข้อมูล SEO

หน้าบทความส่งเนื้อหาจาก server ให้ผู้อ่านและ crawler มีชื่อ/description, canonical URL, Open Graph และ `BlogPosting` JSON-LD ตามข้อมูลจริงของบทความ พร้อมวันเผยแพร่และวันปรับปรุง `/sitemap.xml` รวมเฉพาะบทความที่เผยแพร่ และ `/robots.txt` ชี้ sitemap หน้า admin เป็น `noindex`

ชื่อ SEO และ description เป็นคำแนะนำให้เครื่องมือค้นหา ไม่รับประกันการจัดอันดับหรือรูปแบบ snippet บทความควรตอบคำถามที่เจ้าของสัตว์เจอจริง อ้างแหล่งข้อมูลที่ตรวจสอบได้ ระบุชื่อผู้เขียน และตรวจความถูกต้องโดยเฉพาะเนื้อหาสุขภาพ หลีกเลี่ยงการเขียนหัวข้อซ้ำเพื่อยัดคำค้น

หลังเปิดใช้ ให้นำ `https://www.chordjai.life/sitemap.xml` ไปส่งใน Google Search Console ของโดเมนและตรวจ URL ของบทความจริง การส่ง sitemap เป็นการช่วยให้ค้นพบหน้า ไม่ใช่การรับประกัน index

แหล่งอ้างอิงการพัฒนา:
- [Google: Article structured data](https://developers.google.com/search/docs/appearance/structured-data/article)
- [Google: Sitemap overview](https://developers.google.com/search/docs/crawling-indexing/sitemaps/overview)
- [Tiptap: React integration](https://tiptap.dev/docs/editor/getting-started/install/react)

## ขอบเขตระบบและสิทธิ์

ไม่มี credential ฝั่ง client หรือ `NEXT_PUBLIC` ใหม่ ทุก endpoint จัดการบทความตรวจเซสชัน Dashboard ปัจจุบันและ Origin สำหรับคำขอที่เปลี่ยนข้อมูล ไม่ใช้สิทธิ์ LINE ของเจ้าของสัตว์แทนสิทธิ์ผู้ดูแล มีอัตราจำกัดคำขอและจำนวนอัปโหลด การแก้ไขมี audit โดยไม่บันทึกเนื้อหาบทความลง audit

ข้อมูลอยู่ใน `analytics.blog_posts` และ `analytics.blog_images` ซึ่งเปิด RLS/FORCE RLS และให้สิทธิ์ worker เท่านั้น Public API เลือกเฉพาะสำเนาที่เผยแพร่ ส่วนรูปสาธารณะตรวจการอ้างอิงในสำเนาที่เผยแพร่ทุกครั้ง ไม่แปลงรูปไดอารี่ส่วนตัวให้เป็นรูป Blog

เนื้อหาเก็บเป็นโครงสร้าง JSON ที่จำกัดชนิด node/mark ไม่รับ HTML/JavaScript/CSS ตามอำเภอใจ รูปต้องมาจากช่องอัปโหลด Blog และลิงก์รับเฉพาะ HTTP(S) หรือเส้นทางภายในที่ปลอดภัย ขนาด/จำนวน/ความลึกของเนื้อหามีเพดาน

รูปที่อัปโหลดแล้วแต่ไม่ได้นำไปใช้ยังคงใช้พื้นที่ Blob การเก็บเข้าคลังไม่ลบไฟล์ถาวร รุ่นนี้ยังไม่มีหน้าจอล้างรูปที่ไม่ใช้หรือการตั้งเวลาเผยแพร่
