# การติดตามน้องผ่าน LINE แบบเลือกเปิดรับ

ระบบนี้เป็นส่วนหนึ่งของวงจรไดอารี่ดูแลน้อง เจ้าของเลือกให้ใช้ข้อมูลที่บันทึกเพื่อกลับมาถามเรื่องเดิมอย่างพอดี ไม่เปิดให้บัญชีเดิมอัตโนมัติ และไม่ใช้เป็นการเฝ้าติดตามฉุกเฉิน

## เจ้าของควบคุมอะไรได้

- เปิด/ปิดการติดตาม เลือกเว้นอย่างน้อย 5 หรือ 7 วัน ค่าเริ่มต้น 7 วัน
- เลือกภาษาไทย/อังกฤษ และพักการติดตาม
- หลังเปิดหรือแก้ตัวเลือก รออย่างน้อย 24 ชั่วโมงก่อนส่งอัตโนมัติ ตัวอย่างข้อความดูได้ทันที
- เลือกแหล่งข้อมูลแยก: ไดอารี่ดูแล สมุดประจำตัว สมุดความทรงจำ และ memory ที่อนุญาตไว้กับผู้ช่วย
- ดูตัวอย่างข้อความโดยไม่ส่ง และดูประวัติส่วนตัวกับคำตอบ LINE

LLM รับเฉพาะข้อมูลจำนวนจำกัดจากแหล่งที่เลือก ไม่รับความรู้สึกส่วนตัวในช่องระบาย ค่าใช้จ่าย รูป หรือประวัติแชทเต็มของผู้ใช้/คนในบ้าน สมุดความทรงจำและเรื่องเล่าใช้เฉพาะที่ผู้ใช้เป็นผู้เขียนเอง Memory ต้องเปิดใช้และยังมีความยินยอมเดิมอยู่ คำตอบ LINE สั้น ๆ ใช้เป็นบริบทได้เมื่อแหล่งต้นทางยังมีสิทธิ์และเข้าถึงได้

## การเลือกข้อความ

`gpt-6.1-sol` เลือกว่าจะส่งหรือข้าม เลือกน้อง แหล่งบันทึก ความตั้งใจของคำถาม หัวข้อที่ตรวจเทียบกับคำในบันทึก เช่น หู การกิน น้ำหนัก และโทนจากชุดตัวเลือกที่ตรวจได้ ข้อความจริงประกอบด้วยชื่อและวันของบันทึกที่มีอยู่ ระบบไม่ให้โมเดลเขียนคำวินิจฉัย ยา หรือคำแนะนำเปลี่ยนการรักษาอย่างอิสระ

กรณีเจ้าของบันทึกว่าไปหาหมอรักษาไรหู ระบบสามารถถามความคืบหน้าจากเรื่องนั้นได้ แต่ไม่สรุปว่าหายแล้วหรือแนะนำให้เริ่ม/หยุดยาจากระยะเวลาที่ผ่านมา ถ้าไม่มีเรื่องที่ควรถามหรือมีอัปเดตที่ตอบคำถามแล้ว โมเดลเลือกข้ามได้

ส่งได้เฉพาะ 09:00–20:00 Asia/Bangkok รวมสัตว์หลายตัวไว้ในโอกาสติดต่อของผู้ใช้คนเดียว และไม่ส่งถี่ขึ้นเพราะมีหลายโปรไฟล์ การเตือนตามกำหนดมีลำดับก่อนข้อความชวนกลับมา ตรวจ active account, service consent, การเป็นเพื่อน OA, source permission และช่วงเว้นระหว่างข้อความก่อนประมวลผลและก่อนส่งอีกครั้ง

## LINE และการตอบกลับ

Cron เรียก notification ผ่าน private service binding แล้วใช้ [LINE Push API](https://developers.line.biz/en/docs/messaging-api/sending-messages/) ส่งถึง LINE user ID ที่ยืนยันแล้ว Webhook เดิมรับ event ที่ตรวจลายเซ็นเพื่อใช้คำสั่ง `พัก`/`PAUSE`/`STOP` และการเริ่มต่อที่ผู้ใช้เลือก

การตอบข้อความติดตามเก็บเป็นคำตอบส่วนตัวอย่างจำกัด ผูกกับข้อความติดตามล่าสุดโดยระบุว่าความเกี่ยวข้องยังไม่ยืนยัน ไม่เปลี่ยน health record หรือสถานะเรื่องการดูแลอัตโนมัติ เก็บข้อความ/คำตอบ 90 วันแล้วลบ ส่วนประวัติการยินยอมอยู่จนลบบัญชี

ลิงก์เปิดแอปใช้ `followupId` เมื่อผู้ใช้ยืนยันตัวตนและยังมีสิทธิ์จึงบันทึกการเปิดได้ LINE รับคำขอไม่ใช่หลักฐานว่าเจ้าของเห็นข้อความ และการเปิด/ตอบไม่พิสูจน์ผลต่อ retention โดยตัวมันเอง

ใช้ delivery UUID เดิมเป็น [LINE retry key](https://developers.line.biz/en/docs/messaging-api/retrying-api-request/) พร้อม lease และ cooldown ใน PostgreSQL เมื่อผลส่งไม่แน่นอนจะไม่ส่งใหม่ด้วย UUID อื่นหลังหมดช่วง retry การปิด/เปลี่ยนสิทธิ์ยกเลิกร่างที่ยังไม่ส่ง บันทึกเดิมที่ยังไม่มีการตอบหรือเปิดอ่านจะถูกถามซ้ำได้ไม่เกินสองครั้งต่อรุ่นข้อมูล แล้วรออัปเดตใหม่

## API และงานเบื้องหลัง

- `GET/PATCH /api/v1/notification/followup/preferences`
- `POST /api/v1/notification/followup/preview` — ไม่ส่ง LINE
- `GET /api/v1/notification/followup/history`
- `POST /api/v1/notification/followup/:id/opened` — authenticated owner only
- `/api/v1/notification/webhooks/line` — webhook เดิม
- `GET /internal/cron/followups` — Cron ที่ยืนยันด้วย secret เรียกทุก 5 นาที ประมวลผลไม่เกินสองผู้ใช้พร้อมกันต่อรอบ

ในช่วงส่ง 11 ชั่วโมงมีเพดานประมาณ 264 การพิจารณาต่อวันก่อนงบ AI/ความพร้อมผู้ให้บริการ ระยะ 5/7 วันเป็นขั้นต่ำในการเว้นข้อความ ไม่ใช่การรับประกันวันส่งสำหรับทุกบัญชี

Migration 18 เพิ่ม preferences, consent ledger, deliveries และ replies พร้อม RLS ใช้ OpenAI/LINE/ฐานข้อมูลและ environment เดิม การทดสอบใช้ provider mocks และ PostgreSQL แยก ไม่ส่งข้อความทดสอบให้ผู้ใช้จริง
