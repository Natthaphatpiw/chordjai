# ป้องกันการ์ด LINE Agent เด้งซ้ำจากปุ่มเก่า

## เหตุการณ์ที่ตรวจพบ

ตรวจ log ของ backend production commit `26a5c19` และอ่านฐานข้อมูลจริงแบบ read-only ในวันที่ 31 ตุลาคม 2026 ไม่ได้ส่งข้อความทดสอบเข้า LINE หรือแก้ข้อมูลของเจ้าของ

- ช่วงวันที่ 30 ตุลาคม เวลา 20:48–20:54 น. (Asia/Bangkok) พบการ์ด `error` ที่ส่งสำเร็จ 9 รายการ ทั้งหมดมีรหัส `AGENT_CHOICE_STALE` และอ้างถึงคนละ turn
- เหตุการณ์จากการกดปุ่มส่วนใหญ่เข้ามาราว 20:44 น. แล้วทยอยประมวลผลผ่าน Cron และคิว retry จนถึง 20:54 น. จึงดูเหมือนระบบส่งเองทุกนาที
- LINE สร้าง `webhookEventId` ใหม่ทุกครั้งที่กดปุ่ม การกันซ้ำด้วย event ID เพียงอย่างเดียวจึงกันการกดปุ่มเดิมซ้ำไม่ได้
- เมื่อประมวลผล ปุ่มดังกล่าวใช้แล้วหรือไม่ตรงกับสถานะ/รุ่นของงาน แต่ระบบเดิมสร้างการ์ดผิดพลาดแยกทุก turn
- ขณะตรวจ คิว `queued`/`running` ว่าง และไม่ต้องลบประวัติหรือยกเลิกงานจริงเพื่อระงับเหตุการณ์นี้ ฐานข้อมูลมี migration รุ่น 26 แล้ว

นี่เป็นการทยอยตอบเหตุการณ์จากปุ่มเก่าหลายเหตุการณ์ ไม่ใช่หลักฐานว่า LINE ส่งการ์ดเดิมซ้ำด้วย retry key เดียวกัน การส่งการ์ดผิดพลาดไม่ได้หมายความว่ามีการสร้างไดอารี่ซ้ำ ต้องตรวจ tool receipts/รายการจริงแยกต่างหาก

## พฤติกรรมหลังแก้

1. ปุ่ม `agent:choice:<uuid>` ของเจ้าของเดียวกันใช้คีย์คิวเดียวกัน แม้แต่ละการกดมี event ID ต่างกัน การกดซ้ำไม่สร้างงานประมวลผลเพิ่ม ไม่ส่ง ACK/loading เพิ่ม และล้าง payload ของเหตุการณ์ที่ซ้ำเมื่อรับเข้าคิวแล้ว
2. ปุ่ม `agent:compose:<uuid>` ยังเปิดแป้นพิมพ์ซ้ำได้ การเปิดแป้นพิมพ์ไม่ถือเป็นคำตอบหรือการอนุมัติ
3. Assistant ตรวจเจ้าของ งาน รุ่น อายุ สถานะ และประเภทปุ่มอีกครั้งก่อนทำงาน ปุ่มที่หมดอายุ ใช้แล้ว หรือเป็นของคำถามก่อนหน้าจบเป็น no-op โดยไม่เรียกโมเดล ไม่เขียนข้อมูลสุขภาพ และไม่สร้างการ์ด error
4. การ์ด `error` ที่ค้างจากโค้ดเก่าและอ้างถึง turn `AGENT_CHOICE_STALE` ถูกปิดด้วย `AGENT_STALE_CHOICE_SUPPRESSED` พร้อมล้างข้อความ ก่อนติดต่อ LINE งานคิวจบได้ตามปกติ
5. Delivery อ่านสถานะใหม่และล็อกแถวหลังได้ user lock ก่อนส่ง ยังคงใช้ LINE retry key เดิมเมื่อ transport ล้มเหลว

Log `line_agent_stage` เพิ่ม stage `stale_choice_ignored` เพื่อแยกเหตุการณ์ปุ่มเก่าจากข้อผิดพลาดจริง ไม่บันทึกชื่อเจ้าของ ชื่อน้อง ข้อความ หรือ LINE ID

## การทดสอบและเปิดใช้

ใช้ PostgreSQL/pgvector แยกในเครื่องกับข้อมูลสังเคราะห์และ mock LINE/OpenAI ตรวจการกดซ้ำพร้อมกัน 9 เหตุการณ์ → 1 งานคิว → 1 บันทึก, ปุ่มเก่า/หมดอายุ, การคงคำถามปัจจุบัน, การระงับ error ที่ค้าง, การเปิดแป้นพิมพ์ซ้ำ และการ retry ขนส่งด้วย key เดิม

ผลวันที่ 31 ตุลาคม 2026: unit tests ผ่าน 342 ข้อ; integration ของ Agent และ input guard ผ่าน 74 ข้อ (55 + 19) ไม่เรียก OpenAI/LINE จริง ชุด integration อื่นที่ต้องตั้ง `TEST_DATABASE_URL` ถูกข้ามในการรัน unit ตามปกติ

การแก้นี้ใช้ตารางเดิม ไม่ต้องเพิ่ม SQL หรือ `.env` ต้อง deploy backend ที่รวมการแก้ก่อนจึงจะเปลี่ยนพฤติกรรมบน LINE จริง ผลทดสอบในเครื่องไม่ใช่ผลยืนยัน deployment จริง
