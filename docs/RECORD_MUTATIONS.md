# แก้ไขและลบบันทึกของน้อง

เจ้าของต้องแก้ข้อมูลที่จดผิดและลบรายการที่ไม่ต้องการได้ โดยไม่ต้องสร้างประวัติทับซ้อน และไม่ทำให้การเตือน น้ำหนักล่าสุด หรือข้อมูลที่แชร์ไว้ยังแสดงค่าฉบับเก่า เอกสารนี้อธิบายส่วนที่เพิ่มวันที่ 29 ตุลาคม 2026 อ่านคู่กับ [LINE Agent](LINE_AGENT.md) และ [ผลตรวจ](VERIFICATION.md)

## บันทึกที่จัดการได้

| ประเภท | ในแอป/LIFF | ผ่าน LINE Agent | ผลของการลบ |
| --- | --- | --- | --- |
| ประวัติสุขภาพ: วัคซีน น้ำหนัก ยา ป้องกันปรสิต โน้ต | แก้ไข/ลบรายรายการ | อ่านรายการ → แก้ไข/ลบ → ยืนยัน | ลบการเตือนที่ผูกกับรายการ คำนวณน้ำหนักล่าสุดจากประวัติที่เหลือ และยกเลิกลิงก์สรุปเก่า |
| ไดอารี่ดูแลน้อง | แก้ไข/ลบ รวมรูปที่แนบและค่าใช้จ่าย | แก้ไข/ลบรายการที่เลือก | ลบตัวบันทึกและข้อมูลย่อยของบันทึก รูปต้นฉบับในคลังยังอยู่ ลิงก์เก่าที่ใช้ข้อมูลนั้นใช้ต่อไม่ได้ |
| เรื่องการดูแล | แก้ชื่อ/สถานะ/ลบกลุ่ม | แก้ไข/ลบกลุ่มที่เลือก | ไดอารี่ในกลุ่มยังอยู่และกลายเป็นบันทึกไม่จัดกลุ่ม |
| หน้าความทรงจำ Story | แก้ไข/ลบทีละหน้า | แก้ไข/ลบหน้าที่เลือก | หน้าอื่นและหน้าปกยังอยู่ รูปต้นฉบับไม่ถูกลบจากคลัง |
| หน้าปกสมุด | แก้ชื่อและของตกแต่ง | อัปเดตหน้าปกที่ตรวจแล้ว | ไม่มีคำสั่งลบสมุดทั้งหมดพร้อมทุกหน้า |
| Pet Passport | แก้คำตอบ/เรื่องที่กังวล/รูป/ข้อมูลที่เลือก และลบ Passport | แก้ร่างหรือคำตอบ/ลบ Passport โดยยืนยันก่อน | คำตอบและข้อมูลใน Passport รวมถึงลิงก์ของฉบับนั้นถูกลบ/ใช้ต่อไม่ได้ ไดอารี่หลังพบหมอที่บันทึกแยกไว้ยังอยู่ |
| ความจำ AI ที่บันทึกไว้ | แก้ไข/ลบทีละข้อในหน้าผู้ช่วย | แก้ไข/ลบได้เมื่อเปิด optional memory และมี consent ปัจจุบัน | ไม่ลบประวัติ Chat หรือความจำข้ออื่น การจัดการในแอปยังทำได้เมื่อปิดการใช้ memory |

ข้อมูลที่เจ้าของมีสิทธิ์อ่านไม่ได้หมายความว่าแก้ต้นฉบับได้ทุกชนิด ประวัติจากผู้เขียนนอกครอบครัว เช่น ต้นฉบับจากคลินิก จะแสดงเป็นอ่านอย่างเดียวสำหรับเจ้าของ ถ้าไม่มีสิทธิ์แก้ แก้ได้เฉพาะส่วนที่เป็นบันทึกของตนหรือข้อมูลครอบครัวที่มีสิทธิ์ และไม่เปลี่ยนผู้เขียนเดิม หลักฐาน OCR และที่มาของข้อมูลให้กลายเป็นข้อมูลใหม่

นัดหมายยังใช้การเลื่อน/ยกเลิกตาม flow ของนัด ข้อมูลความยินยอมและสิทธิ์ใช้หน้าตั้งค่า ส่วนประวัติระบบ/หลักฐานวิจัย/บันทึกต้นฉบับของคลินิกไม่ได้เปิด generic CRUD ให้ผู้ใช้แก้ตามใจ เอกสารนี้ไม่อ้างว่าทุกตารางในฐานข้อมูลแก้หรือลบผ่านแชทได้

## ข้อความสำหรับทดสอบกับพีโอนี

ก่อนถึงคลินิก ใช้ข้อความที่แสดงว่าเหตุการณ์ยังไม่เกิดขึ้น เช่น

> บันทึกไดอารี่ของพีโอนีให้หน่อย วันนี้กำลังจะพาไปหยอดหลังคอเพื่อจัดการไรหู ตอนนี้ยังไม่ได้ไปคลินิก

หลังรับบริการแล้ว จึงเล่าสิ่งที่เกิดขึ้นจริง ถ้าทราบชื่อยา คำแนะนำ ค่าใช้จ่าย และวันนัด ให้ใส่ข้อมูลที่ได้รับมา ระบบไม่ควรเติมช่องเหล่านั้นเอง

ต้องการทดสอบการถามเพิ่ม ให้เริ่มด้วย

> ช่วยบันทึกไดอารี่ของพีโอนีให้หน่อย เดี๋ยวฉันเล่ารายละเอียดในข้อความถัดไป

จากนั้นตอบคำถามด้วยเหตุการณ์จริง ระบบควรแจ้งว่ากำลังทำงาน แล้วส่งผลพร้อมปุ่ม LIFF ให้เปิดรายการนั้น การมี optional field ว่าง เช่น ชื่อยา/ราคา ไม่จำเป็นต้องทำให้ระบบถามทุกช่อง

ตัวอย่างคำสั่งแก้ไข หลังแทนข้อความในวงเล็บด้วยชื่อ/วันที่จริง:

> แก้บันทึกไดอารี่ชื่อ [ชื่อรายการ] ของพีโอนี วันที่ [วันที่ของบันทึก] ให้เพิ่มค่าใช้จ่าย [จำนวนเงินจริง] บาท ส่วนข้อมูลเดิมอย่างอื่นคงไว้

> แก้บันทึกน้ำหนักของพีโอนีวันที่ [วันที่จริง] จาก [ค่าเดิม] เป็น [ค่าที่ถูกต้อง] กิโลกรัม

ตัวอย่างคำสั่งลบ:

> ลบบันทึกชื่อ [ชื่อรายการ] ของพีโอนี วันที่ [วันที่ของบันทึก] ให้หน่อย

Agent ต้องอ่านข้อมูลก่อน แสดงชื่อสัตว์ รายการและวันที่ปัจจุบัน แล้วขอยืนยันแยก หากไม่ตรงให้ตอบ “ยกเลิก” หรือแก้รายละเอียด ไม่เลือกตัวแรกจากรายการที่กำกวมเอง งานแก้/ลบไม่เริ่มจากเพียงข้อความถามวิธีใช้

## การยืนยันและข้อมูลที่เปลี่ยนจากอีกอุปกรณ์

- ประวัติสุขภาพส่ง `revision` ซึ่งคำนวณจากข้อมูลปัจจุบัน; ไดอารี่ เรื่องการดูแล Story และ Passport ใช้ `version`
- แก้ไขหรือลบฉบับเก่าต้องได้ `409 VERSION_CONFLICT` เพื่อโหลดฉบับล่าสุดและตรวจใหม่ ปุ่ม LINE เก่าหรือการตอบยืนยันก่อนออกคำถามรุ่นล่าสุดใช้แทนกันไม่ได้
- การลบเป็นการลบถาวร ไม่มีถังขยะในแอป การยืนยันระบุชื่อน้อง ชื่อรายการและวันที่ ไม่อาศัย UUID อย่างเดียว
- UI ใช้ idempotency key คงเดิมเมื่อ retry คำขอเดียวกัน Agent เก็บ prepared receipt ที่มีเฉพาะ reference ก่อนส่ง DELETE เพื่อรับผลเดิมหลัง transport failure โดยยังตรวจสิทธิ์ในน้องและใช้ API/idempotency เดิม ไม่เก็บสำเนาข้อมูลส่วนตัวใน receipt
- ผลลบสำเร็จเปิดหน้าประวัติที่เหลือผ่าน LIFF ไม่พาไปยัง resource ที่ถูกลบแล้ว หากเกิด version conflict ต้องเริ่มคำขอใหม่เพื่อตรวจข้อมูลล่าสุด ไม่ retry ลบฉบับใหม่แบบอัตโนมัติ
- Escape/ยกเลิกในหน้าแก้ไขที่มี draft ต้องเคารพการเลือกเก็บ draft และการเปลี่ยนภาษาไม่ทิ้งข้อความที่กำลังแก้

## ฐานข้อมูลรุ่น 23

Migration [`202610290023_record_mutations.sql`](../supabase/migrations/202610290023_record_mutations.sql) เพิ่ม trigger ที่ทำเฉพาะการดูแลข้อมูลที่ผูกกับ source เดิมใน transaction เดียว:

1. การเตือนของ health record ซึ่งอาจเป็นของผู้ดูแลร่วม ต้องเปลี่ยนตามวันนัด/ชื่อที่แก้ และหายเมื่อเจ้าของลบรายการ
2. น้ำหนักล่าสุดต้องมาจากรายการที่เหลือหลังแก้ ลบ หรือเปลี่ยนชนิดรายการ ไม่ใช้ค่าที่ลบไปแล้ว
3. สรุปสุขภาพเก่าที่ไม่มี source IDs ต้องเพิกถอนเมื่อแก้ประวัติสุขภาพ ส่วนสรุปที่มี source และ Passport ต้องยกเลิกฉบับเก่าเมื่อข้อมูลที่เลือกเปลี่ยน
4. เมื่อเอาไดอารี่ออกจากกลุ่มหรือลบ Passport ที่อ้างอยู่ version ของไดอารี่ที่ได้รับผลต้องเปลี่ยนด้วย

API ยังคงตรวจ actor/RLS/ผู้เขียนและใช้ whitelist ของ field ที่แก้ได้ ฟังก์ชันสิทธิ์สูงเรียกตรงจาก app/worker ไม่ได้ และไม่ใช่เส้นทางทำ CRUD แทนผู้ใช้

ฐานข้อมูลเดิมใช้ `diagnostic.sql` → `upgrade.sql` → `diagnostic.sql` ไม่ใช้ bootstrap ซ้ำ ไม่เพิ่ม `.env` ใหม่ ระบบที่ยังไม่ถึงรุ่น 23 จะไม่เปิดปุ่มแก้/ลบประวัติสุขภาพและแก้ไดอารี่/กลุ่มที่ต้องพึ่งความสอดคล้องนี้ API ตอบ `RECORD_MUTATIONS_UPGRADE_REQUIRED` แทนการแก้ข้อมูลโดยไม่มี trigger ดู [DEPLOYMENT.md](DEPLOYMENT.md)

ผู้ดูแลแจ้งว่ารันรุ่น 23 แล้ว และ read-only diagnostic ยืนยัน fingerprint `171c466a888ddd5fd7df4ab1f5055527` ไม่มีการรัน migration หรือแก้ env จริงโดย agent

การทดสอบอัตโนมัติใช้ PostgreSQL แยกและ browser fixtures ไม่สร้างหรือลบบันทึกพีโอนีจริง ผู้ใช้เป็นผู้ทดสอบบทสนทนาจริงเอง ผลที่ตรวจล่าสุดอยู่ใน [VERIFICATION.md](VERIFICATION.md)
