# Pet Passport: เตรียมพบหมอด้วยบทสนทนา

พัฒนา 13 ตุลาคม 2026 บนฐานข้อมูลรุ่น 21 ต่อจากไดอารี่และสิทธิ์คลินิกเดิม ไม่ต้องสร้าง repository หรือ Vercel project เพิ่ม และไม่มี environment variable ใหม่ ใช้ OpenAI config เดิม (`gpt-6.1-sol`), private Blob, LINE และ scheduler เดิม

## เจ้าของใช้อย่างไร

เปิด **สมุดสุขภาพ → ไดอารี่ดูแลน้อง → เตรียมพบคุณหมอ** หรือปุ่ม Pet Passport ในสมุดประจำตัว เริ่มได้แม้ยังไม่มีไดอารี่ เล่าเหตุที่อยากพบหมอ เลือกเรื่องการดูแล ประวัติเดิมและรูปประกอบได้ แล้วตอบทีละคำถาม

ระบบปรับหมวดคำถามจากสิ่งที่เล่าและคำตอบ เช่น หู ผิวหนัง การเดิน ระบบหายใจ หรืออาเจียน/ขับถ่าย มีตัวเลือกไม่ทราบ จำไม่ได้ และไม่เกี่ยวข้อง การตอบว่าไม่ทราบทำให้ถามใหม่ให้อธิบายง่ายขึ้นได้หนึ่งครั้ง ก่อนเก็บว่าไม่ทราบตามจริง ร่างและคำตอบเก็บไว้เปิดกลับมาต่อได้ ภาษาไทย/อังกฤษเปลี่ยนได้โดยไม่แปลหรือเขียนทับคำพูดเจ้าของ

คำถามสัญญาณฉุกเฉินมาก่อนการถามตามปกติ เมื่อพบข้อมูลที่เข้ากฎจะแสดงทางติดต่อสัตวแพทย์ทันที ไม่ให้รอจบบทสนทนา การตรวจนี้เป็นกฎเบื้องต้น ไม่ใช่การรับรองความปลอดภัยหรือแทนการตรวจร่างกาย

เจ้าของแก้เหตุที่มาและคำตอบ เลือกประวัติ/รูปที่จะเปิดเผย แล้วตรวจและกดยืนยันก่อนแชร์ การยืนยันสร้างฉบับคงที่ซึ่งเก็บคำตอบเดิม สถานะไม่ทราบ วันเวลาและแหล่งที่มา ไม่ให้ AI เติมข้อเท็จจริงหรือคำวินิจฉัยให้

รูปสูงสุดห้ารูปต่อ Passport ใช้รูปที่เจ้าของอัปโหลดสำหรับน้องตัวเดียวกันและพร้อมใช้งาน ถ่ายรูปหรือเลือกจากเครื่องได้ รูปที่เลือกให้หมออ่านไม่ได้ส่งไป OpenAI ในฟีเจอร์นี้ และไม่ได้เข้า PetID หรือการฝึกโมเดลโดยอัตโนมัติ

## วิธีให้หมออ่าน

**ลิงก์อ่านสรุป:** เจ้าของเลือกเปิดเผยฉบับยืนยันให้ผู้ถือครองลิงก์ อายุ 1–14 วัน เพิกถอนได้ หน้าลิงก์มีสรุปคำตอบสำคัญ Q&A ต้นฉบับ ประวัติที่เลือก รูปและการพิมพ์ ผู้มีลิงก์อ่านได้โดยไม่ต้องสมัคร แต่เขียนบันทึกจากคลินิกผ่านลิงก์ไม่ได้

**Clinic Portal:** เจ้าของต้องเลือกเผยแพร่ฉบับยืนยันให้คลินิก และให้สิทธิ์ `passport.read` แยกที่ **ตั้งค่า → ดูแลร่วม → สิทธิ์ข้อมูลให้คลินิก** สิทธิ์เดิมไม่เปิด Passport เพิ่มเอง คลินิกที่ยืนยันแล้วและสมาชิกที่ยังมีสิทธิ์จะเปิดจากเมนู Pet Passport หรือทางลัดในนัดหมายได้

หากต้องการให้บัญชีสัตวแพทย์เพิ่มสิ่งที่ตรวจพบ การรักษา คำแนะนำและวันติดตาม เจ้าของเลือก `passport.write` เพิ่ม โดยต้องมีสิทธิ์อ่านด้วย ทั้งบทบาทบัญชีและสมาชิกคลินิกต้องเป็นสัตวแพทย์ บันทึกนี้ผูกกับฉบับที่อ่าน ณ ตอนเขียน และแสดงแยกจากคำตอบของเจ้าของ ไม่แก้คำตอบเดิม ไม่ใช่การตรวจสอบใบประกอบวิชาชีพโดยอัตโนมัติ

รูปใน Clinic Portal โหลดผ่าน Bearer-authenticated endpoint และตรวจสิทธิ์ก่อนและหลังอ่าน bytes แล้วแสดงด้วย Blob URL ชั่วคราว ส่วนรูปลิงก์สาธารณะตรวจ capability อายุลิงก์ ฉบับปัจจุบันและสิทธิ์เจ้าของทุกครั้ง ไม่มีการออก capability รูปทั่วไปให้คลินิก

## หลังพบหมอและ LINE

เจ้าของกลับมาเลือกบันทึกผลหลังพบหมอ หรือเลือกบันทึกจากคลินิกเป็นร่าง เจ้าของตรวจ/แก้ข้อมูล เติมรูป ค่าใช้จ่ายและวันนัด แล้วกดยืนยันก่อนลงไดอารี่ หากยังไม่มีเรื่องการดูแล ระบบสร้างเรื่องไว้เชื่อมการอัปเดตถัดไป คำขอซ้ำไม่เพิ่มไดอารี่หรือวันเตือนซ้ำ

บันทึกในไดอารี่ยังเป็นข้อมูลที่เจ้าของรายงาน พร้อม lineage ระบุว่าเจ้าของอ้างอิงบันทึกคลินิกหรือจดเอง การแก้ข้อความไม่ได้ทำให้ข้อความใหม่กลายเป็นข้อมูลที่คลินิกยืนยัน และไม่แก้เนื้อหา Passport ที่ยืนยันไว้ก่อนเข้าพบ

วันติดตามสร้าง reminder ผ่านระบบเดิม การส่งแจ้งเตือนขึ้นกับสิทธิ์และสถานะบัญชี LINE ของผู้ใช้ การบันทึกไม่ส่ง LINE ทันที และไม่เปิด optional follow-up เอง

หากเจ้าของเปิด LINE follow-up และเลือกแหล่งไดอารี่ไว้ ข้อมูลหลังพบหมอจะเป็นแหล่งที่ใช้เลือกคำถามต่อได้ เช่น อาการหลังไปพบหมอเปลี่ยนอย่างไร ระบบเดิมยังตรวจความยินยอมล่าสุด เว้นอย่างน้อย 5 หรือ 7 วัน เวลาเงียบ ความสำคัญของ reminder และการพักเรื่องเดิม ไม่มีรูป ค่าใช้จ่ายหรือช่องความรู้สึกส่วนตัวส่งเข้า AI follow-up

## ขอบเขต AI

ใช้ `passport.question` ผ่าน OpenAI client กลาง: โมเดลเลือกได้เฉพาะรหัสคำถามที่ยังเกี่ยวข้องจากชุดที่ระบบกำหนด ไม่สร้างข้อความถามทางคลินิกใหม่ ข้อเท็จจริง การวินิจฉัย หรือการรักษา ผลยังผ่าน schema validation และการเลือกคำถาม/ความเร่งด่วนตามกฎ ถ้า AI ไม่พร้อม โควตาหมด หรือเครือข่ายขัดข้อง ยังตอบตามชุดคำถามที่ควบคุมได้

โมเดลได้รับเหตุที่มาและคำตอบของเจ้าของเท่านั้น ไม่มีภาพ ความรู้สึกส่วนตัว ค่าใช้จ่าย หรือประวัติที่ไม่ได้เลือก การพัฒนารอบนี้ไม่เรียก OpenAI หรือส่ง LINE จริง การทดสอบผู้ให้บริการใช้ mocks และการทดสอบข้อมูลใช้ฐานข้อมูลแยก

## สิทธิ์ การแก้และการลบ

- ร่างและประวัติคำตอบเป็นของเจ้าของน้อง ผู้ดูแลร่วมไม่ได้เห็นโดยอัตโนมัติ
- เมื่อแก้เหตุที่มา คำตอบ ประวัติที่เลือกหรือรูป จะปิดการเข้าถึงฉบับเดิม ต้องตรวจและยืนยันใหม่
- การถอนสิทธิ์ใช้บริการ เปลี่ยนเจ้าของ บัญชีไม่ใช้งาน ลบรูป หรือเปลี่ยน/ลบประวัติต้นทางที่เลือก ทำให้ฉบับเดิมเปิดต่อไม่ได้ การยินยอมใหม่ไม่เปิดลิงก์เก่ากลับมา
- ถอน/หมดอายุสิทธิ์คลินิกแล้วคลินิกอ่านข้อมูลและรูปหรือเพิ่มบันทึกต่อไม่ได้
- ประวัติคำตอบ ฉบับยืนยันและบันทึกคลินิกเป็น append-only ส่วนเนื้อหาไดอารี่เจ้าของแก้ได้ตามกฎเดิม
- Personal data export รวมร่าง คำตอบ ฉบับยืนยัน การเชื่อมรูป บันทึกคลินิกที่มีสิทธิ์และข้อมูลลิงก์ที่ไม่รวม capability ลบบัญชีเจ้าของแล้วข้อมูล Passport และสิทธิ์ตามบัญชี cascade
- ลิงก์ที่เพิกถอนหยุดการเข้าถึงครั้งถัดไป แต่สำเนาที่ผู้อ่านพิมพ์หรือดาวน์โหลดแล้วเรียกคืนไม่ได้

## API

| กลุ่ม | เส้นทาง |
| --- | --- |
| เจ้าของ | `GET/POST /api/v1/health/passport/sessions`, `GET/PATCH/DELETE /sessions/:id` |
| คำตอบ/ยืนยัน/หลังพบหมอ | `POST /api/v1/health/passport/sessions/:id/answers`, `/confirm`, `/after-visit` |
| ลิงก์เจ้าของ | `GET/POST /api/v1/share/passports`, `DELETE /passports/:id` |
| ผู้อ่านลิงก์ | `GET /api/v1/share/public/passport/:token`, `/:token/media/:mediaId` |
| คลินิก | `GET /api/v1/clinic/pets/:petId/passports?clinicId=...`, `GET /clinic/passports/:sessionId?clinicId=...` |
| รูป/บันทึกคลินิก | `GET /api/v1/clinic/passports/:sessionId/media/:mediaId?clinicId=...`, `POST /clinic/passports/:sessionId/notes` |

การสร้างใช้ client/request UUID และ hash ของ body การแก้/ยืนยันใช้ version ตรวจการทับข้อมูล endpoint ที่เกี่ยวกับสิทธิ์ไม่ใช้ generic cached mutation response เพื่อให้ตรวจสิทธิ์ปัจจุบันซ้ำทุกครั้ง

## หลักฐานการออกแบบและสิ่งที่ต้องวัด

[AAHA: The Team Approach](https://www.aaha.org/resources/2023-aaha-selected-endocrinopathies-of-dogs-and-cats-guidelines/the-team-approach/) สนับสนุนการเริ่มคำถามปลายเปิดแล้วถามเจาะจง ทวนคำตอบ และปรับตามเหตุที่มาพบหมอ [Cornell Emergency and Critical Care](https://www.vet.cornell.edu/hospitals/services/emergency-and-critical-care-0) อธิบายการคัดกรองก่อนประวัติ/การตรวจเต็มรูปแบบ การประยุกต์นี้ยังต้องประเมินชุดคำถามและความปลอดภัยร่วมกับสัตวแพทย์จริง

ยังไม่มีหลักฐานว่า ChordJai ลดเวลาซักประวัติ เพิ่มความแม่นยำการรักษา หรือเพิ่ม retention ต้องวัดเวลาทำ Q&A/จุดที่เลิกตอบ ข้อผิดพลาดและความไม่ครบของข้อมูล การใช้สรุปจริงโดยหมอ และการอัปเดตหลังพบหมอเทียบ flow เดิม การเปิดลิงก์ไม่ใช่หลักฐานว่าหมออ่านหรือใช้รักษาแล้ว
